Hospital infection control: do earlier transfers improve prediction?¶

Complex Systems and Applications — completed Option 1

The analysis below uses the published synthetic course data for the hospital infection control project.

Portfolio summary¶

This project asks whether earlier patient transfers improve prediction of a new simulated infection cluster over the next 14 days. Among 120 synthetic wards, 102 were eligible because they had no active cluster at the observation point. I compared logistic regression using occupancy and device-use share with the same model adding total incoming transfers and transfers from initially affected wards. Both used the same stratified 71/31 training/test split, with scaling fitted only on training data. Adding network features increased F1 from 0.435 to 0.737 and ROC AUC from 0.693 to 0.904; accuracy increased from 0.581 to 0.839. The network model missed five of twelve later clusters and produced no false alarms. Total incoming volume measures all recorded arrivals; the other feature counts arrivals from affected sources. These results describe one small synthetic test set and do not establish transmission or clinical usefulness. In practice, missed clusters could delay investigation and false alarms could divert staff; infection-control professionals would need to review any flags.

Prediction point: the end of the 14-day transfer recording window. The two ward attributes, earlier transfers and initial cluster status are known at this point. The target describes a new simulated cluster over the following 14 days.

Part 2: directed, weighted transfer network¶

Each ward is a node. An edge from ward A to ward B means recorded transfers from A to B, and its transfer_count is the number of transfers in the preceding window. All 120 wards remain in the graph, including the 18 excluded from the prediction sample. Their known initial states are needed to calculate exposure at eligible wards.

  • incoming_volume: the sum of transfer counts on every incoming edge.
  • from_active_volume: the sum on incoming edges whose source ward was affected at the start.

Both features use information available at the observation point. Neither uses the later target.

    sum(edge['transfer_count'] for source, _, edge in G.in_edges(ward_id, data=True)

    for ward_id in wards['ward_id']
]

Part 3: a fair logistic regression comparison¶

Model A: occupancy ratio and device-use share. Model B: the same attributes plus incoming volume and volume from initially affected wards.

Both models use the same eligible wards, a single stratified split with random_state=123, and a 30% test fraction. Each pipeline fits its scaler and logistic regression using only the training rows. Logistic regression uses the default L2 regularization and C=1.0; no hyperparameters or thresholds are tuned on the test set. Hard predictions use the classifier's default decision boundary at probability 0.5.

This evaluates previously unlabelled wards in one network whose earlier links and initial states are already known. It does not test forecasting a new time window or transferring the model to an independent hospital network.

def fit_and_score(columns):
    model = make_pipeline(
        StandardScaler(),
        LogisticRegression(C=1.0, solver='lbfgs', max_iter=1000),
    )
    X_train = eligible.loc[train_ids, columns]
    X_test = eligible.loc[test_ids, columns]
    model.fit(X_train, y.loc[train_ids])
    predicted = model.predict(X_test)
    probabilities = model.predict_proba(X_test)[:, 1]
    scores = {
        'Accuracy': accuracy_score(y.loc[test_ids], predicted),
        'F1': f1_score(y.loc[test_ids], predicted, zero_division=0),
        # Completed marker 6: AUC receives probabilities, not binary decisions.
        'ROC AUC': roc_auc_score(y.loc[test_ids], probabilities),
    }
    return scores, predicted, probabilities

base_scores, base_pred, base_prob = fit_and_score(original)
network_scores, network_pred, network_prob = fit_and_score(with_network)
results = pd.DataFrame(

Final interpretation¶

Adding the two network features improves all three metrics on this fixed test set: accuracy rises from 0.581 to 0.839, F1 from 0.435 to 0.737 and ROC AUC from 0.693 to 0.904. These are observed differences on 31 wards, not estimates of a guaranteed benefit in a new hospital.

Model A identifies 5 of 12 later clusters, misses 7 and raises 6 false alarms. Model B identifies 7, misses 5 and raises no false alarms. Its recall is therefore 7/12 = 0.583: the high precision of 1.000 does not mean it detects every later cluster. One changed test prediction would change accuracy by about 3.2 percentage points.

The two network features have different meanings. Total incoming volume measures all earlier arrivals. Volume from initially affected sources incorporates information about the known state of neighbouring wards. Their predictive association cannot establish which patients were infected, when transmission happened, or whether transfers caused clusters. The source status is measured at the observation point, not continuously throughout the preceding transfer window.

The synthetic outcome rule deliberately includes both network features. That makes this a test of recovering signal in a small constructed sample. The single split, synthetic setting and absence of independent hospitals limit any broader conclusion. Wards also share a graph; the random node split does not establish independence or generalization to a different network.

Ethics. If such flags were ever considered in practice, missed clusters could delay investigation, while false alarms could divert infection-control resources and burden patients and staff. Infection-control professionals would need to review flags together with clinical evidence before action. These synthetic results do not support deployment.

Reflection¶

The comparison is reproducible because both models use identical rows and training-only scaling. The main conceptual challenge is keeping the prediction sample separate from the graph: initially affected wards are excluded from the target but retained as known sources of incoming transfers. With more time, repeated validation within the training data could assess sensitivity to the split, followed by evaluation on genuinely new data; realistic clinical conclusions would require an appropriate real dataset and study design. The part worth carrying to other networked systems is the bookkeeping: a component's own measurements and the connections that link it to its neighbours are two different things, and both have to be kept free of later information for the comparison to mean anything.
